# Module: RAG Sidecar

## Purpose
The RAG (Retrieval-Augmented Generation) sidecar handles indexing, chunking, and semantic querying of RFP documents, proposal history, and internal compliance materials. It utilizes ChromaDB as a vector store and calls a local Ollama service for embeddings and LLM analysis.

## Language & Runtime
- **Language**: Python 3.11
- **Key Libraries**:
  - `chromadb`: High-performance vector database client for local document collections.
  - `ollama`: Official Python client for local LLM inference and embeddings generation.
  - `pydantic`: Validation and parsing of document chunks and search results.
- **Entry point**: `sidecars/rag/src_py/server.py`

## IPC Interface (Standard I/O JSON-RPC 2.0)
Communicates directly with the Tauri shell using stdin/stdout pipes, avoiding TCP networking ports.
- **Methods Received**:
  - `ingest_document`: Extracts text from a document, generates sliding-window paragraph chunks, calculates vector embeddings using Ollama, and inserts them into ChromaDB.
  - `query_rag`: Queries ChromaDB for top-k relevant context chunks, constructs a RAG prompt, and streams semantic answers from the local LLM.
- **Events Emitted**:
  - `ingest_complete`: Success signal with total chunk count.
  - `query_response`: Streams response chunks generated by the LLM back to the chat UI.
  - `error`: Traced exception states for missing files or connection failures.

## Internal Structure
- `server.py`: Stream-based JSON-RPC reader and async method dispatcher.
- `chroma_client.py`: Collection management and similarity distance querying interfaces.
- `ollama_client.py`: Direct connection hooks for generating embeddings (`nomic-embed-text`) and executing chat completions (`deepseek-r1` or `llama3`).
- `ingest.py`: Core document parsing pipeline.

## External Service Dependencies
- **Ollama (`http://localhost:11434`)**: Must be running locally on the user's host machine.
- **ChromaDB**: Runs as a local vector database.
